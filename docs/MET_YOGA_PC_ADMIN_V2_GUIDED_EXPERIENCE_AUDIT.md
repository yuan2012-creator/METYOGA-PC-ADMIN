# MET YOGA PC 后台 V2 一级页面引导式体验总巡检

**用于判断 9 个一级页面是否符合「结果 → 风险 / 分类 → 动作 → 明细入口」的门店经营使用逻辑**  
**当前阶段：V2 母版 + 店长视角 + 产品与权益一级模块 + 引导式分层优化完成后**

**巡检方式：** 只读代码与归档文档，未改任何页面。  
**巡检日期：** 2026-06-21  
**代码基准：** `components/v2/*` 各 `*V2Page.tsx`、`*viewModel.ts`；`docs/MET_YOGA_PC_ADMIN_V2_TEMPLATE_ARCHIVE.md`；`docs/MET_YOGA_PC_ADMIN_V2_STORE_MANAGER_DASHBOARD_AND_PRODUCT_RIGHTS_PLAN.md`

---

## 1. 总体结论

### 1.1 一句话判断

**当前 V2 已完成「业务模块完整性」和「角色视角原型」，但各一级页面的引导式程度不一致。**  
已从「能演示」进入「部分角色可用」，尚未全面进入「不培训也能用」。

### 1.2 阶段判断

| 维度 | 状态 |
|------|------|
| 8+1 一级模块母版 | ✅ 完成 |
| 全局视觉 / 抽屉统一 | ✅ 完成 |
| 店长经营驾驶舱 | ✅ 方向成立，仍可减负 |
| 产品与权益独立一级 + 引导分层 | ✅ 当前最优样板之一 |
| 全站角色可用 | ⚠️ 仅 Dashboard 接角色；其余页 mock 固定门店/总部 |
| 跨模块动作下钻 | ❌ 几乎全部为 toast，无真实跳转 |
| 二级页面 | ❌ 未建设（符合当前阶段） |

### 1.3 成熟页面 vs 高学习成本页面

**已较成熟（引导结构清晰，或执行导向强）：**

- 今日运营 — 最接近「店长执行台」样板
- 经营总览 · 店长视角 — 明确按结果→分类→动作→入口设计
- 产品与权益 — P0.2 分层后结构最清晰
- 系统设置 — 控制中心定位清楚，首屏不膨胀
- 活动与获客 — 漏斗 + 队列完整，局部重复可优化

**仍有明显学习成本（信息密度高、结论/动作不够前置）：**

- 师资与团队 — 区块最多、滚动最长
- 会员经营 — 缺顶部一句话结论，区块并列
- 课程与排课 — 判断与证据层混排，周排班 lane 认知负担大
- 财务与资产 — 口径正确但人话解释仍靠用户自己拼
- 经营总览 · 总部视角 — 多店对比强，但「今天先做什么」弱于店长视角

### 1.4 是否建议继续逐页改造

**建议继续，但采用「逐页 P0 认知降本」，不要一次性改 9 页。**

理由：

1. 母版方向正确，没有偏离「判断页 / 执行台 / 控制中心」定位
2. 问题主要是**信息层级与动作优先级**，不是推倒重做
3. 产品与权益、店长驾驶舱已验证「结果→风险→动作→入口」有效
4. 其余页面可复用同一套改造手法，成本低、风险小

### 1.5 是否建议立刻做二级页面

**不建议立刻大规模建设二级页面。**

建议顺序：

1. **先做一级页认知降本**（会员 / 课程 / 师资 / 财务优先）
2. **再定二级页面 IA**（会员名单、线索池、卡项配置、规则编辑等）
3. **最后接真实接口与权限**

一级页当前职责应是「判断 + 优先级 + 入口」，明细继续放抽屉或 toast 占位即可。

### 3.1 经营总览 · 总部视角

#### 3.1.1 页面定位是否清楚

承担**总部 / 投资人多店经营判断**：确认收入、实收、预收负债、现金安全、多店对比。  
**未偏离**归档定位（§3），不是报表流水，也不是执行台。

#### 3.1.2 当前优点

1. 首屏「经营诊断」有一句话结论 + P0 标签
2. 四指标卡区分实收 / 确认收入 / 预收负债 / 覆盖率
3. 风险处理队列具备 fact / impact / 建议动作结构
4. 多店经营对比用结构条 + 现金安全线，非纯表格
5. 经营利润趋势与课程交付摘要补充趋势上下文

#### 3.1.3 当前问题

1. **缺「总部本周 / 今日优先动作」** — 有队列但偏风险复核，不够「先做什么」
2. 多店对比区信息量大，**第一眼更重数据而非动作**
3. 店长视角切换后标题仍为「经营总览」，与「门店经营驾驶舱」并存，**角色心智略分裂**
4. 所有下钻为 toast，总部无法「点进模块」验证路径
5. Hero 部分证据格有硬编码痕迹，与 viewModel 结论略脱节

#### 3.1.4 是否符合引导结构

| 层级 | 当前是否具备 | 问题 | 建议 |
|------|:------------:|------|------|
| 结果 | 是 | 经营诊断结论清晰 | 保持 |
| 风险 / 分类 | 是 | 风险队列 + 多店状态 | 多店区增加「最需关注店」一句话 |
| 动作 | 部分 | 队列有按钮但偏「查看详情」 | 增加 3–5 条「本周经营动作」 |
| 明细入口 | 是 | 多店查看详情 | 保持 toast，二级页后再接 |

#### 3.1.5 建议改造方向

- 在风险队列下增加「本周总部关注动作」轻量区（可复用店长视角 weekActions 结构）
- 多店对比首行保留 highlights，弱化 per-store 默认展开感
- HQ 视角与店长视角切换时，副标题区分更明显

#### 3.1.6 是否建议立即改代码

**暂不改** — 店长视角已补位；总部视角 P1，等会员/财务等执行链路模块降本后再统一加「跨模块动作」。

### 3.2 经营总览 · 店长视角（门店经营驾驶舱）

#### 3.2.1 页面定位是否清楚

承担**单店经营理解层**：30 秒知道本店状态、最大风险、今天/本周先做什么、进哪个模块。  
**明显优于**普通总部经营总览复制版，符合补充方案（方案 A）。

#### 3.2.2 当前优点

1. 顶部结论卡：门店 + 状态（观察）+ 主要原因 + 判断来源
2. 8 核心指标带状态与人话解释
3. 「今日优先动作」≤3 条，P0/P1 清晰
4. 「经营问题分类」五类归因，每类有入口
5. 「经营明细入口」不铺大表，只做轻量链接

#### 3.2.3 当前问题

1. **整页仍偏长** — 结论 + 8 指标 + 3 动作 + 5 分类 + 6 结构 + 5 周动作 + 6 入口，**30 秒能懂状态，但 3 分钟才能扫完**
2. 「门店经营结构」6 卡与上方 8 指标有**信息重复**（耗课、现金、会员等）
3. 所有按钮 toast，店长无法形成「点完真的去了会员经营」的心智闭环
4. 仅 Dashboard 接角色，其他模块未随店长角色变门店范围
5. 财务身份进入经营总览时仍可能看到 HQ 多店内容（角色未全链路）

#### 3.2.4 是否符合引导结构

| 层级 | 当前是否具备 | 问题 | 建议 |
|------|:------------:|------|------|
| 结果 | 是 | 结论卡完整 | 保持 |
| 风险 / 分类 | 是 | 五类问题分类 | 保持 |
| 动作 | 是 | 今日 + 本周队列 | 保持今日 3 条置顶 |
| 明细入口 | 是 | 6 个轻量入口 | 二级页前保持 |

#### 3.2.5 建议改造方向

- **合并重复：**「门店经营结构」6 卡可收成 3–4 张，或与 8 指标做折叠「查看依据」
- 首屏只保留：结论 + 4 个最关键指标 + 今日动作；其余默认第二屏
- 待其他模块 P0 降本后，再打通 toast → 真实 `onNavigate` 带筛选

#### 3.2.6 是否建议立即改代码

**先观察** — 结构已是最优样板之一；优先改会员/课程/师资/财务，再回头减负驾驶舱。

3. 门店固定滨江馆 mock，未接角色切换

#### 3.3.4 是否符合引导结构

| 动作 | 是 | 快捷操作 + 队列按钮 | 保持 |
| 明细入口 | 部分 | 课程卡片可点 | 保持 |

#### 3.3.5 建议改造方向

- 合并「当前最紧急」进「必须今天处理」，侧边只留快捷操作 + 简报

**Pass / 暂不动** — 作为其他页面学习样板；仅在做 P1 时合并重复队列。

### 3.4 会员经营

**会员生命周期与服务 / 销售经营**，S0–S6、风险、跟进、匹配。

4. 页面纵向长，底部「重点会员」到达率低
5. 与店长驾驶舱「会员风险」联动仅为 toast 文案

#### 3.4.4 是否符合引导结构

| 层级 | 当前是否具备 | 问题 | 建议 |

| 结果 | 否 | 缺顶部结论 | 增加「会员经营状态」hero |

| 动作 | 部分 | 有待办队列，不够尖 | 今日会员动作 3–5 条置顶 |

#### 3.4.5 建议改造方向

- 顶部增加：**会员经营结论**（如：续费窗口 28 人、低频风险 42 人、今日需跟进 6 人）
- 第一屏：结论 + 今日动作 + 服务/销售队列摘要（各 3 条）
- 生命周期图、匹配、风险图谱**下沉**为第二屏
- 视觉降权：匹配区保持但不与 P0 队列抢首屏

#### 3.4.6 是否建议立即改代码

**立即改** — P0 首选页之一；改造面可控（viewModel 增 hero + todayActions，TSX 调序）。

## 4. 重点页面判断

### 4.1 店长视角 / 门店经营驾驶舱是否成立

| 是否仍信息过多 | ⚠️ 8 指标 + 6 结构卡重复，建议第二屏合并 |
| 是否需进一步简化 | 建议减负，非推倒 |

店长身份默认进入此视图，**角色策略正确**。下一步是**减负与跨模块跳转**，不是重写结构。

### 4.2 产品与权益作为一级模块是否成立

**结论：成立，比系统设置长抽屉更合理。**

| 检查项 | 判断 |

| 是否比设置抽屉更清晰 | ✅ P0.2 分层后明显 |
| 是否需拆二级页 | ✅ 卡项 / 商城 / 合同 迟早要拆 |
| 当前是否需继续减负 | 一级已够，不宜再堆 |
| 卡项/积分/合同是否表达清楚 | ✅ 七分类 + 红线 + 权限 |

与系统设置关系：**设置看健康与入口，一级模块做规则中心** — 需在文案上强化，避免双入口困惑。

### 4.3 系统设置是否回归控制中心

**结论：基本回归，未滑向大仓库。**

- 主屏 4 区：健康 / 入口地图 / 高风险 / 日志
- 规则明细在抽屉，符合「控制中心」定义
- 产品与权益外迁后，设置不再承担产品配置主战场 ✅

### 4.4 今日运营是否最接近店长执行台样板

**结论：是，建议作为 P0 改造页的参考样板。**

今日运营优势：

- 时间轴强化「现在」
- 动作队列贴近当日
- 快捷操作符合前台行为
- 信息量比师资/财务可控

可复用模式：**结论（可选一行）→ 紧急队列 → 快捷入口 → 明细摘要**。

## 5. 全局共性问题

1. **卡片密度不均** — 师资、财务、课程、店长驾驶舱偏高；今日、设置较低
2. **模块都想表达完整闭环** — 每页含判断+证据+队列+摘要，母版演示必要，一线使用过重
3. **入口多、优先级不够** — 大量「查看」「去处理」按钮，toast 文案相似
4. **角色差异仅停留在 Dashboard + 侧栏身份卡** — 各页 mock 仍固定「滨江馆」或「总部」
5. **跨模块下钻未打通** — 驾驶舱写「进入会员经营」，实际仅 toast
6. **队列重复** — 今日（紧急 vs 必须处理）、营销（作战台 vs 线索队列）
7. **待建设 toast 密度高** — 用户多次点击后易疲劳，需控制首屏可点数量
8. **财务口径需反复培训** — 虽有区分，店长仍易混淆实收/确认收入/预收
9. **页面底部区块到达率低** — 会员重点会员、课程周 lane、师资成长区
10. **二级页缺失导致一级被迫承载明细** — 周排班 lane、门店财务矩阵等

## 6. 全局优化原则

1. **一级页只解决判断与入口** — 不做完整 CRUD、不做流水明细
2. **二级页解决名单与明细** — 会员名单、线索池、卡项列表、排课 lane 全量
3. **抽屉解决证据与单对象详情** — 会员、课程、老师、资产、活动、线索
4. **顶部必须有一句话结论** — 人话，带状态标签
5. **每页最多突出 3–5 个优先动作** — P0/P1 置顶，其余下沉
6. **复杂规则归入配置中心** — 产品与权益、系统设置，不在业务页改规则
7. **店长页面先讲人话，再讲指标** — 指标带一句解释
8. **总部页面也要给动作** — 不能只有趋势和多店对比
9. **财务页必须区分实收 / 确认收入 / 预收负债** — 用人话摘要重复强化
10. **产品与权益区分卡项、积分、赠送权益、合同** — 不混排为「商品」
11. **不要把复杂度推给一线** — 前台/管家/店长不应拼模块关系
