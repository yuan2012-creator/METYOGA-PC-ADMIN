# MET YOGA 管理后台 · P0 live 接入前置依赖确认清单 v1

**读者**：前端、后端、云函数 / 运维负责人  
**性质**：依赖与责任确认清单；**不替代**接口设计文档或 OpenAPI 契约。  
**前提**：本仓库当前**没有**可运行的云函数目录、云环境工程配置、真实登录态与门店上下文；在未补齐下列项之前，**不应**开始 `memberQuery` 的 live 编码联调。

## 1. 当前结论（截至本清单编写时）

| 项 | 结论 |
|----|------|

| 登录态 | **无真实登录态**：应用入口为本地导航状态，未见统一 Auth / Session / Token 提供层。 |
| 角色来源 | **无真实角色来源**：`ReadonlyQueryParams.role` 等为类型预留，未见从鉴权系统注入。 |
| 门店范围来源 | **无真实门店范围来源**：`storeId` 等为类型与业务字段预留，未见从租户/门店上下文注入。 |

| memberQuery live 编码 | **当前不建议直接进入**：缺云侧、身份、门店与调用通道；强行编码将导致无法验收或与生产安全模型冲突。 |

| 6 | 云函数部署方式 | 云函数 / 运维 | 微信云开发控制台上传 / CI / Serverless 框架等。 |

| 8 | 用户角色由谁提供 | 后端 | RBAC 模型；与前端 `role` 字符串如何映射。 |

**确认后怎么继续**：将结论同步到《memberQuery 后端契约确认 v1》及 `apiClient` 设计评审；由后端提供**可调用**的测试端点或云函数名 + 入参样例；前端再在 `services` 层实现 live 分支（仍禁止在 `components` 内直连云或 fetch）。

## 3. 需要后端提供的第一批接口（契约前占位）

下列为 **P0 只读查询** 建议顺序；**「是否存在」与「谁开发」须由后端/云负责人勾选**，本清单不预设已存在。

### 3.1 总表字段说明（每行接口均需填写）

- **是否已存在**：是 / 否 / 部分（仅 mock 或内部脚本）。  
- **若不存在谁开发**：后端团队 / 云函数负责人 / 外包方等。  
- **最小返回字段**：与当前 `memberAdapter` 等对齐的**最小可读字段集**（具体列在契约文档中展开）。  
- **是否只读**：本清单默认 **是**；若某接口非只读须显式标注并移出 P0 只读批次。  
- **权限校验**：默认 **必须**；匿名或仅演示环境除外（须书面豁免）。  
- **门店范围过滤**：默认 **必须**；总部全量须有单独规则与审计。

## 4. 前端接入前置条件（必须具备再改 live 代码）

| # | 条件 | 说明 |
|---|------|------|
| 1 | `apiClient` 知道如何调用 live | 统一入口：云函数名 + payload，或 HTTP baseURL + path；超时与重试策略已定。 |
| 2 | 环境变量或配置来源 | 如 `VITE_*` 或运行时注入；**生产禁止静默回退 mock**（与准备文档一致）。 |
| 3 | 当前用户身份 | 可解析的稳定 `userId` / `subject`；与后端 JWT 或会话一致。 |
| 4 | 当前角色 | 与 RBAC 对齐；缺省时行为定义（拒绝 vs 最小权限）。 |
| 5 | 当前 `storeId` / `storeIds` | 与登录态绑定；多门店 UI 与请求参数一致。 |
| 6 | 统一错误结构 | 与 `ReadonlyApiError` 映射；含稳定 `code` 与可读 `message`。 |
| 7 | 分页结构 | 与 `ReadonlyApiMeta` 的 `page`、`pageSize`、`total`、`hasMore` 一致或可映射。 |
| 8 | 测试数据 | 测试云中有可重复造测的会员/门店数据。 |
| 9 | 错误用例覆盖 | **403 / 404 / 422 / 500** 及网络失败在测试环境可复现，前端有对应错误态验收。 |

## 5. 不允许做的事（全员遵守）

| # | 禁止项 |
|---|--------|
| 1 | **不允许**在 `components` 里直接写 `wx.cloud.callFunction`。 |
| 2 | **不允许**组件内直接 `fetch` / `axios` 调后端（须经 `services` + 统一客户端）。 |
| 3 | **不允许**绕过 `service` / `adapter` 把云返回塞给 UI。 |
| 4 | **不允许** live 失败后**静默 fallback** 到 mock 数据。 |
| 5 | **不允许**财务页面 **mock 与 live 混算**（同源、同会话、同模块数据源一致）。 |
| 6 | **不允许**没有**角色和门店范围**就接真实数据（防越权与数据泄露）。 |
| 7 | **不允许**在 P0 只读阶段先接**写入**接口。 |
| 8 | **不允许**前端直连数据库集合（仅通过云函数或 BFF）。 |

## 6. 推荐推进顺序（依赖顺序）

| 步骤 | 动作 | 产出 |
|------|------|------|
| **第一步** | 后端 / 前端 / 云负责人共同确认：调用方式、云环境、登录态、角色、门店范围 | 签字或纪要 + 环境信息表 |
| **第二步** | 提供 **`memberQuery`** 测试云函数或 BFF 接口（含样例请求/响应） | 可联调端点 + 测试账号 |
| **第三步** | 前端在 **`apiClient`**（或等价模块）增加 **live** 调用分支 | 代码评审通过、单测/手测通过 |
| **第四步** | **`memberService`** 的 live 模式从 `REAL_API_NOT_CONNECTED` 改为真实调用（mock 保留） | 双路径可切换 |
| **第五步** | **`Members`** 在 live 下验收 **loading / error / empty / 分页 / 门店过滤** | 验收记录 |
| **第六步** | 再进入 **`memberAssetQuery`** | 同上 |
| **第七步** | 再进入订单、合同、支付、课程等后续接口（按准备文档顺序） | 分阶段发布 |
