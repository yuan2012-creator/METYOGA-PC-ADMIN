## 1. 当前阶段结论

**MET YOGA PC 后台 V2 已完成第一批 P0 二级页面 mock 版。**

当前后台已经形成三层结构：

| 层级 | 职责 | 代表形态 |
|------|------|----------|
| **一级页：判断层** | 回答「好不好？先做什么？进哪里？」 | Hero 结论卡、优先动作队列、配置分类、明细入口 |
| **二级页：处理层** | 回答「有哪些？筛哪些？批量怎么处理？」 | 状态摘要、筛选、Tab、结构化列表 / 卡片、批量操作区 |
| **抽屉：单对象详情与证据链层** | 回答「这个对象详情是什么？证据够不够？」 | 概览、规则、证据链、操作日志、建议动作 |

### 从一级页到二级页的能力跃迁

当前已经从：

- 一级页面能看懂经营状态；
- 能看到优先动作；
- 能进入明细入口；

进一步进入：

- 可进入**会员名单**；
- 可处理**高余额低耗课名单**；
- 可查看**退费 / 冻结 / 转卡申请**；
- 可查看**完整周排课**并发起**新增排课 mock**；
- 可查看**老师端申请审批**；
- 可查看**卡项配置**；
- 可查看**积分商城配置**。

### 当前仍然不是生产系统

明确不做、未接入：

| 类别 | 说明 |
|------|------|
| 数据 | 不接真实接口；数据来自各模块独立 `*Secondary*.viewModel.ts` |
| 审批 | 不做真实审批；通过 / 驳回均为 toast「（待建设）」 |
| 资产变更 | 不做真实退款、冻结、转卡 |
| 排课 | 不做真实排课发布；不出现排课成功、已开放预约 |
| 师资 | 不做真实老师端同步 |
| 产品权益 | 不做真实卡项上下架、合同编辑、会员端发布 |
| 积分商城 | 不做真实积分兑换、库存更新、权益发放 |
| 权限 | 不做真实权限控制；角色视角为文案与按钮态 mock |
| 通知 | 不做真实消息通知、自动群发 |

所有写入类操作统一为 **toast「（待建设）」** 或 **mock 流程占位**；操作日志、审批时间线、证据链均为展示态，不承担真实业务写入。

## 3. 当前二级页面通用实现方式

### 3.1 技术模式

当前 7 个 P0 二级页面均采用：

| 规则 | 说明 |
|------|------|
| 模块内部视图切换 | 在 `*V2Page.tsx` 内用 `useState` 切换 `overview` ↔ 二级视图，**不修改 `App.tsx` 路由** |
| 不新增左侧菜单 | 左侧 9 项主导航保持不变；二级页从一级页明细入口进入 |
| 二级页顶部返回 | 均有「返回 xxx」按钮，回到对应一级页 `overview` |
| 独立 mock 数据 | 各二级页数据维护在 `*Secondary*.viewModel.ts`，不污染一级页 snapshot |
| 写入类按钮 | 统一 toast「（待建设）」；不出现真实成功态文案 |
| 抽屉承接详情 | 复用 `met-v2-drawer-*` 规范；列表 / 卡片点击打开详情抽屉 |
| 不做真实业务写入 | 保存、提交、通过、驳回、上下架、排课发布、兑换发放均不持久化 |

### 3.2 视图切换一览

| 一级模块 | 宿主页面 | 二级视图 key | 返回文案 |
|----------|----------|--------------|----------|
| 会员经营 | `MemberV2Page` | `memberList` / `highBalance` | 返回会员经营 |
| 财务与资产 | `FinanceV2Page` | `assetChangeRequests` | 返回财务与资产 |
| 课程与排课 | `CourseV2Page` | `weekSchedule` | 返回课程与排课 |
| 师资与团队 | `StaffV2Page` | `teacherApplications` | 返回师资与团队 |
| 产品与权益 | `ProductRightsV2Page` | `cardConfig` / `pointsMall` | 返回产品与权益 |

### 3.3 阶段判断

**当前这种方式适合原型阶段**，因为：

- 降低路由复杂度，一级导航稳定；
- 产品、运营、店长可快速走查完整 IA；
- 各模块可独立迭代，不牵动全局路由表。

**但后续如果二级页面继续增加**（P1 预计 7+ 页），需要评估是否进入正式路由体系，否则将出现：

- 深链与刷新丢失视图状态；
- 跨模块跳转难以携带上下文；
- 二级页头部 / 筛选 / 卡片样式重复维护；
- viewModel 类型命名分散，不利接口契约对齐。

## 4. P0-1 会员名单 / 会员详情页归档

### 4.1 页面目标

承接会员经营一级页的会员明细入口，支持按阶段、风险、资产、负责人和跟进状态查看会员，为会员跟进、约课和后续风险名单提供统一名单基础。

### 4.2 来源入口

| 入口类型 | 具体位置 |
|----------|----------|
| 会员经营一级页 | 页头 / 重点会员入口 / 后续配置入口 |
| 今日会员优先动作 | 带 `opensMemberList` 的 P0/P1 动作项 |
| 生命周期分层 | 各阶段「查看名单」类入口 |
| 会员风险图谱 | 风险节点下钻 |
| 重点会员入口 | 「查看全部会员」 |
| 服务 / 销售任务队列 | `serviceViewAllKey` / `salesViewAllKey` 等 |
| 后续可承接 | 今日运营、财务会员资产风险、老师名下会员（结构已预留） |

### 4.3 当前页面结构

1. **页面头部** — 返回、标题、面包屑、范围说明、规则提示
2. **会员状态摘要** — 轻量数字卡（总数、待跟进、高风险等）
3. **筛选区** — 门店、阶段 S0–S6、风险、负责人、跟进状态、关键词
4. **会员列表** — 结构化会员卡 / 行，非 Excel 大表
5. **批量操作区** — 批量分配、批量标记（toast mock）
6. **会员详情抽屉** — 复用 `MemberV2MemberDetail` 扩展字段
7. **空状态** — 无数据、筛选无结果、权限不足 fallback

### 4.4 关键能力

- 会员名单**不是 Excel 大表**；每行含状态、阶段、风险、负责人、建议动作
- **P0 / 高风险会员置顶**
- 会员手机号**脱敏**展示
- 支持打开**会员详情抽屉**
- 支持 mock **跟进、约课、标记已处理**（toast）
- 为高余额低耗课名单、老师名下会员、财务风险名单提供**共用名单结构基础**

### 4.5 业务红线

- 不显示完整手机号
- 不显示身份证、住址、银行卡
- 不做群发、自动召回
- 不做真实跟进保存、真实预约
- 不把会员名单做成电话销售 CRM

### 4.6 验收结论

**P0-1 已完成，可作为会员类二级页面基础版本。**

## 5. P0-2 高余额低耗课会员名单归档

|----------|----------|

| 会员名单 | 可从名单页跳转或共享详情抽屉 |
| 财务与资产 | 会员资产风险相关入口（结构预留） |
| 店长经营驾驶舱 | 跨模块风险下钻（规划位） |
| 会员资产风险队列 | `risk_list` / 高余额相关 CTA |

### 5.3 当前页面结构

1. **页面头部** — 返回会员经营；可返回会员名单
2. **风险摘要** — 高余额低耗课人数、P0/P1 分布
3. **风险规则说明** — 口径与免责声明
4. **筛选区** — 门店、风险等级、剩余点数区间、未到店天数、负责人
5. **风险名单列表** — 结构化风险卡，非退费金额表
6. **处理建议区** — 规则建议动作
7. **批量操作区** — 批量分配、批量标记（toast mock）
8. **会员详情抽屉** — 复用 P0-1 会员详情抽屉

### 5.4 关键能力

- **P0 / P1 / P2** 风险分级展示
- **剩余点数**与**剩余金额估算**展示（带免责）
- **未到店天数**展示
- **风险原因**与**建议动作**同行可见
- **证据完整度**展示（如沟通、约课、到店记录 mock）
- **复用会员详情抽屉**，避免重复建设

### 5.5 业务红线

- 剩余金额估算**不等于可退金额**
- 赠送权益**不计入**可退金额
- 积分**不当现金**
- 不做群发、自动召回
- 不做真实分配、真实预约

### 5.6 验收结论

**P0-2 已完成，可作为会员风险名单类二级页样板。**

## 6. P0-3 退费 / 冻结 / 转卡申请列表归档

### 6.1 页面目标

承接财务与资产中的资产变更处理，统一查看退费、冻结、转卡申请与证据链状态，为财务、店长、总部提供申请处理层。

### 6.2 来源入口

| 入口类型 | 具体位置 |
|----------|----------|
| 财务与资产一级页 | 页头「退费 / 冻结 / 转卡申请」、优先动作 |

| 退款 / 冻结 / 转卡处理区 | `assetChangeSummary` 各状态卡 |
| 会员资产风险队列 | 资产变更相关队列 |
| 财务明细入口 | `detailEntries` 中退费 / 冻结 / 转卡项 |
| 后续联动 | 会员详情、产品与权益卡项规则（结构预留） |

### 6.3 当前页面结构

1. **页面头部** — 返回财务与资产、范围、规则 disclaimer
2. **顶部状态摘要** — 待处理、证据待补、待复核等
3. **类型 Tab** — 全部 / 退费 / 冻结 / 转卡
4. **筛选区** — 门店、状态、证据状态、负责人、关键词
5. **申请列表** — 结构化申请卡，非传统退款后台
6. **证据链状态** — 列表行展示证据完成度（如 4/7）
7. **申请详情抽屉** — 独立 `AssetChange` 详情抽屉（非会员抽屉复用）
8. **批量操作区** — 批量标记、批量导出占位（toast）
9. **空状态** — 无申请、筛选无结果

### 6.4 关键能力

- **退费 / 冻结 / 转卡**三类申请统一处理
- **证据待补 / 待复核置顶**
- **7 项证据链**展示（合同、支付、耗课、签到、积分、沟通等 mock）
- **审批状态 mock**（待复核、已通过 mock、已驳回 mock）
- **金额 / 权益估算**（带免责，非最终退款额）
- **操作日志 mock**
- **独立申请详情抽屉**，与会员详情分离

### 6.5 业务红线

- 不出现**退款成功**、**已到账**
- 不出现**真实审批通过**
- 金额估算**不代表**最终退款金额
- 赠送权益**不计入**退费
- 积分**不当现金**
- 不混淆**实收、确认收入、预收负债、经营利润**
- **老师不可见**此页（角色文案体现）

### 6.6 验收结论

**P0-3 已完成，可作为资产变更申请类二级页样板。**
