# MET YOGA PC 后台｜云函数接口拆分设计 v1

> **目标**：微信云函数（或等价 BFF）在接入真实数据时的**按域拆分**、**只读优先**、**写入与审批边界**约定。  
> **原则**：本文档为设计稿；云函数实际目录名、运行时、鉴权方式（云开发 `openid` / 自定义登录 / 服务间密钥）由工程落地时确定。

---

## 1. 云函数拆分原则

- **按业务域拆分，不按页面拆分**：例如「会员」「订单」「场次」各成独立云函数或子路由，避免把 `Dashboard`、`Mall` 页面名写进函数名导致重复与耦合。
- **先只读，后写入**：P0 仅上线 `xxxQuery`；`xxxCommand` 在只读稳定、权限与日志通道就绪后分批开放。
- **写入必须服务端校验**：所有 `Command` 在云函数内完成参数校验、门店范围、状态机、幂等；前端不得携带「管理员绕过」标志。
- **涉及钱、权益、合同、签到、退款、冻结、转卡、财务分录、老师等级、权限的数据，不能前端直写**：前端仅调用 `Command` 生成**意图**（申请单/草稿单），由服务端事务落库。
- **所有敏感写入必须记录 OperationLog**：与业务主表同一事务或可靠异步（最终一致需补偿）；字段至少含：`actorId`、`action`、`targetType`、`targetId`、`payloadHash`、`requestId`、`result`、`createdAt`。
- **需要审批的操作必须生成申请单 / 审批单**：`Command` 第一步写入 `*_requests` / `approvals` 为 `pending`；审批通过后再执行第二个内部步骤或独立 `approvalConsumer` 云函数。

## 3. P1 写入 / 申请类云函数

> **统一约定**：`Command` **不表示**前端直连改表；表示「服务端执行动作或创建申请单」。**真实写入**＝云函数内对业务库有 insert/update 且非仅草稿（以各函数说明为准）。

### `bookingCommand`

| 项 | 说明 |
|----|------|
| **负责操作** | 创建/取消预约、候补变更 |
| **是否真实写入** | 是（预约事实表） |
| **是否需要审批** | 一般否；大额协议课或特殊规则可配置审批 |
| **是否需要日志** | 是 |
| **是否需要通知** | 取消/改期建议通知会员 |
| **前置校验** | 场次状态、`bookable`、容量、会员状态、重复预约 |
| **禁止前端绕过** | 必须传 `idempotencyKey`；服务端重算金额与权益，不信任前端 `status` 覆盖 |

## 4. 敏感操作统一流程

```
前端发起申请
  → 云函数校验权限（角色 + 门店/数据范围）
  → 校验业务规则（状态机、余额、时间窗、幂等键）
  → 生成申请单 / 命令记录（pending）
  → 审批通过（人工或规则自动）
  → 服务端事务写入业务主表与关联表
  → 写 OperationLog（与事务同事务或可靠队列）
  → 发通知（站内/模板消息/企业微信等，按配置）
  → 前端刷新只读数据（调用对应 xxxQuery）
```

**说明**：仅低风险直写（如普通预约在策略允许内）可压缩为「校验 → 事务 → 日志 → 通知」，但仍必须 **OperationLog**。

## 5. 权限规则（按角色）

### 总部管理员

| 维度 | 建议 |
|------|------|
| **可读范围** | 全集团只读 Query；审计台全量（脱敏策略） |
| **可发起操作** | 规则发布申请、跨店协调类 Command（受审批约束） |
| **禁止操作** | 绕过财务直接过账、私自导出全量 PII |
| **是否可导出** | 是，需走 `exportAudit` / 审批任务 |
| **是否可审批** | 是（规则/权限/大额等） |

### 投资人

| 维度 | 建议 |
|------|------|
| **可读范围** | 脱敏报表、`investmentAggregate`（若单独函数） |
| **可发起操作** | 无写业务 Command；或仅个人测算草稿 |
| **禁止操作** | 全部 P1 `Command` |
| **是否可导出** | 仅脱敏摘要，禁止原始订单导出 |
| **是否可审批** | 否 |

### 店长

| 维度 | 建议 |
|------|------|
| **可读范围** | 本店全量 Query |
| **可发起操作** | 本店预约/签到（策略内）、场次变更申请、退款/冻结/转卡**申请** |
| **禁止操作** | 他店数据、财务分录过账、全局规则发布 |
| **是否可导出** | 本店范围，审批后 |
| **是否可审批** | 本店范围内中级审批（按政策） |

### 运营 / 前台

| 维度 | 建议 |
|------|------|
| **可读范围** | 本店会员/场次/预约只读 |
| **可发起操作** | 代约、签到协助（非补签）、活动查询 |
| **禁止操作** | 退款终审、资产发放冲正、分录、权限 |
| **是否可导出** | 默认否或脱敏小批量 |
| **是否可审批** | 否 |

### 财务

| 维度 | 建议 |
|------|------|
| **可读范围** | 本店或授权范围支付/退款/分录只读 |
| **可发起操作** | 对账标记、退款处理流转、`financeLedgerCommand` 中授权步骤 |
| **禁止操作** | 教务取消课、改老师等级（除非兼任且授权） |
| **是否可导出** | 是（审批 + 水印） |
| **是否可审批** | 是（退款/冲正等） |

### 老师

| 维度 | 建议 |
|------|------|
| **可读范围** | 本人课表、本场次学员名单（脱敏手机号） |
| **可发起操作** | 协助签到（若开放）、课堂备注申请 |
| **禁止操作** | 退款、资产、合同、规则、权限 |
| **是否可导出** | 否 |
| **是否可审批** | 否 |

### 合作门店管理员

| 维度 | 建议 |
|------|------|
| **可读范围** | 本合作店授权与经营摘要（合同约束） |
| **可发起操作** | 数据回填上传、异议申请 |
| **禁止操作** | 总部财务与其他门店、直接改授权法务状态 |
| **是否可导出** | 仅本店且审批 |
| **是否可审批** | 否（或仅限本店内部流程，不审总部单） |

## 6. 云函数命名建议

| 模式 | 含义 | 示例 |
|------|------|------|
| `xxxQuery` | 只读查询 | `memberQuery`、`orderQuery` |
| `xxxCommand` | 写入 / 申请 / 状态变更 | `refundRequestCommand` |
| `xxxAudit` | 审计、导出任务、合规留痕 | `exportAudit`、`accessAudit` |
| `xxxAggregate` | 聚合报表 / 看板 | `dashboardAggregate`、`financeAggregate` |

**可选拆分**：单域 `member` 云函数内用 `action: query|command` 路由，仍须在文档与监控上按 **Query / Command** 区分限流与权限。
