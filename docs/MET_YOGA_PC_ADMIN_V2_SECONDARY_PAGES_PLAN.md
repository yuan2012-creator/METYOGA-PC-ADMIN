## 1. 当前阶段判断

### 1.1 一级页面已稳定

MET YOGA PC 后台 V2 已完成 9 个一级模块母版、P0 四页引导式优化、产品与权益 P0.2 分层、角色视角与全局抽屉统一。**当前不应继续细抠一级页文案与样式。**

一级页职责已经明确：

| 职责 | 说明 |
|------|------|
| 判断当前状态 | Hero 结论卡：健康 / 观察 / 预警 + 关键证据 |
| 给出优先动作 | P0/P1/P2 处理队列：影响、负责人、来源、建议动作 |
| 做问题分类 | 按业务类型拆开：风险、供给、资产、申请等 |
| 提供明细入口 | 轻量按钮 / 小卡，指向二级页（当前 toast 占位） |
| 抽屉承接单对象详情 | 会员 / 课程 / 老师 / 资产 / 财务证据等 |

### 1.2 二级页面是下一阶段的「处理层」

下一阶段二级页面的职责：

| 职责 | 说明 |
|------|------|
| 承接名单 | 可筛选、可排序、可分页的会员 / 课程 / 申请 / 商品列表 |
| 承接明细 | 单对象完整字段、历史记录、关联对象 |
| 承接筛选 | 门店、时间、状态、负责人、风险等级等多维筛选 |
| 承接批量处理 | 批量分配、批量标记、批量导出占位（mock） |
| 承接审批流 | 申请状态机、节点、证据链（mock 审批） |
| 承接配置编辑 | 卡项、积分商品、规则参数（mock 保存） |
| 承接操作日志 | 谁在何时对什么做了什么（mock 展示） |
| 承接证据链 | 合同、支付、耗课、签到、积分、沟通记录 |

### 1.3 核心定位

**二级页面不是重新做一级页，也不是把一级页改成表格。**

二级页面是从一级页下钻出来的**处理层**：

```
一级页（判断层）→ 二级页（处理层）→ 抽屉（单对象详情层）
```

- 一级页回答：「好不好？先做什么？进哪里？」
- 二级页回答：「有哪些？筛哪些？批量怎么处理？」
- 抽屉回答：「这个对象详情是什么？证据够不够？下一步动作？」

## 2. 二级页面设计总原则

以下 14 条原则适用于所有二级页面建设：

| # | 原则 |
|---|------|
| 1 | **一级页负责判断，二级页负责处理** — 不在二级页重复 Hero 结论，但可有轻量状态摘要 |
| 2 | **二级页可以有列表，但不能回退成传统大表后台** — 每行必须有状态、风险、负责人、下一动作 |
| 3 | **必须保留「结论 / 筛选 / 状态 / 操作 / 证据」结构** — 不是 Excel 导出视图 |
| 4 | **必须支持返回一级页** — 页面头部有明确返回入口 |
| 5 | **必须能打开现有右侧抽屉** — 复用 `met-v2-drawer-*`，必要时扩展字段 |
| 6 | **必须有清晰筛选条件** — 按页面类型展示，不堆砌全部筛选项 |
| 7 | **必须有状态字段** — 列表行、摘要区、详情抽屉三处状态一致 |
| 8 | **必须有操作日志意识** — mock 阶段展示日志占位，不接真实写入 |
| 9 | **必须考虑角色权限** — 可见字段、可操作按钮按角色区分 |
| 10 | **暂时仍为 mock，不接真实接口** — 数据来自独立 `*Secondary.viewModel.ts` |
| 11 | **不做真实审批、真实退款、真实排课成功、真实合同编辑** — 全部 toast「（待建设）」 |
| 12 | **所有写入动作仍为 toast 占位** — 保存 / 提交 / 通过 / 驳回均不持久化 |
| 13 | **不出现 AI 推荐** — 匹配、补员、邀约均为规则建议 |
| 14 | **不出现自动群发** — 补员、召回、通知均强调点对点 |

### 技术边界（当前阶段）

- **路由：** 二级页初期可采用「一级页内嵌子视图」或「独立 route 占位」，规划阶段不强制改 `App.tsx`；实施时每次只加一个入口
- **导航：** 左侧 9 项主导航**不新增**二级菜单项；二级页从一级页明细入口进入
- **视觉：** 复用 V2 设计 token、`met-v2-*` 抽屉规范、卡片圆角与按钮层级
- **数据：** 每页独立 viewModel；可引用一级页 drawer mock 中的对象 ID 做联动

## 4. 二级页面通用页面模板

所有二级页面应遵守以下统一模板（按页面类型裁剪区块）。

### 4.1 页面头部

| 元素 | 必填 | 说明 |
|------|:----:|------|
| 返回上一级 | ✅ | 返回来源一级页，保留筛选上下文（mock 可用 session state） |
| 页面标题 | ✅ | 如「会员名单」「退费申请列表」 |
| 来源一级模块 | ✅ | 面包屑：会员经营 > 会员名单 |
| 当前门店 / 周期 / 角色范围 | ✅ | 如「滨江馆 · 本周 · 店长视角」 |
| 页面说明 | 推荐 | 一句话说明本页处理什么 |
| 关键状态摘要 | 推荐 | 如「待处理 12 · 高风险 3」 |
| 主要操作按钮 | 按需 | 如「新增排课」「导出（待建设）」 |

### 4.2 筛选区

按需展示，**不要全部堆上去**：

| 筛选项 | 适用页面 |
|--------|----------|
| 门店 | 几乎全部 |
| 时间范围 | 名单、申请、排课、日志 |
| 状态 | 几乎全部 |
| 负责人 | 会员、线索、申请 |
| 风险等级 | 会员、资产、申请 |
| 会员阶段 S0–S6 | 会员名单 |
| 课程类型 | 排课、老师 |
| 老师 | 排课、申请 |
| 卡项 | 会员、资产变更 |
| 来源渠道 | 线索、活动 |
| 关键词搜索 | 会员名、老师名、申请单号 |

筛选交互：筛选变更后更新状态摘要 + 列表；保留「重置筛选」。

### 4.3 状态摘要区

轻量数字条，不等同一级页 Hero：

| 指标 | 说明 |
|------|------|
| 当前总数 | 符合筛选条件的记录数 |
| 待处理数 | `pendingReview` / `evidencePending` 等 |
| 高风险数 | P0 风险等级记录 |
| 今日 / 本周新增 | 时间范围内新增 |
| 已完成 | `completedMock` 等终态 |
| 异常 | 证据缺失、冲突、逾期 |
| 逾期 | 超过 SLA 未处理（mock 规则） |

### 4.4 列表 / 卡片区

| 规则 | 说明 |
|------|------|
| 形式 | 推荐「结构化列表行」或「卡片列表」，非 Excel 密集大表 |
| 每行必含 | 状态标签、对象名、风险等级、负责人、建议下一动作 |
| 排序 | 高风险置顶；同等级按时间 / 金额 / 余额排序 |
| 字段前置 | 名称、状态、风险、负责人、关键数字 |
| 证据字段 | 不在列表铺满，显示「证据 4/7」点进抽屉 |
| 批量 | 可选勾选 + 批量分配 / 批量标记（toast） |
| 分页 | mock 阶段可前端分页，预留每页 20/50 |

### 4.5 右侧抽屉联动

```
二级页列表行点击 → 打开抽屉（复用或扩展）
抽屉内：概览 / 证据链 / 操作记录 / 建议动作 / 关联跳转
```

| 对象类型 | 抽屉复用来源 |
|----------|--------------|
| 会员 | `MemberV2MemberDetail`（`drawerMemberDetails`） |
| 课程场次 | `CourseV2Detail`（`courseDetailMap`） |
| 老师 | `StaffV2TeacherDetail`（`teacherDetailMap`） |
| 资产 / 财务 | `AssetDetail` / `FinanceDetail`（`financeV2`） |
| 卡项 / 商品 | 新建 `ProductRightsDetail`（扩展 product-rights mock） |
| 申请单 | 新建 `AssetChangeRequestDetail` |

二级页负责**筛选和批量视图**，抽屉负责**单对象详情**。

### 4.6 空状态 / 异常状态

| 状态 | 展示 |
|------|------|
| 无数据 | 「暂无记录」+ 返回一级页或调整筛选建议 |
| 无权限 | 「当前角色不可查看此页面」+ 说明可见角色 |
| 数据加载失败 | 「加载失败，请重试（待建设）」 |
| 筛选无结果 | 「无符合筛选条件的记录」+ 重置筛选按钮 |
| 当前角色不可操作 | 按钮置灰 + tooltip 说明 |
| 功能待建设 | toast「（待建设）」，不写成功文案 |

### 4.7 操作与日志

| 规则 | 说明 |
|------|------|
| 所有操作 | 当前阶段 toast 占位 |
| 真实系统 | 每次操作写入操作日志 |
| mock 阶段 | 抽屉内展示 2–3 条 mock 操作记录 |
| 审批 / 退款 / 排课 / 上下架 | 按钮文案含「提交审核（待建设）」等，**不出现成功态** |
| 危险操作 | 二次确认弹窗（mock），确认后仍 toast |

## 5. P0 二级页面 1：会员名单 / 会员详情页

### 5.1 功能名称

**会员名单 / 会员详情页**

### 5.2 来源入口

| 来源 | 入口位置 | 当前状态 |
|------|----------|----------|
| 会员经营 | 重点会员、明细入口、生命周期分区「查看名单」 | toast 占位 |
| 今日运营 | 会员提醒队列「查看会员」 | toast 占位 |
| 店长经营驾驶舱 | 会员风险动作「进入会员经营」 | toast 占位 |
| 财务与资产 | 会员资产风险队列 | toast 占位 |
| 师资与团队 | 老师名下会员风险「查看名下会员」 | 打开老师抽屉 |

预设路由 ID（实施参考）：`member-list`

### 5.3 功能目标

让店长、管家、运营能**查看会员名单**，并按 S0–S6、风险、资产、跟进状态筛选会员；点击行打开会员详情抽屉，后续可升级为全屏详情页。

### 5.4 目标用户

| 角色 | 使用场景 |
|------|----------|
| 店长 | 查看本店会员全貌，分配跟进，处理高风险 |
| 管家 / 前台 | 日常服务跟进、约课、记录沟通 |
| 运营负责人 | 跨店会员策略、人群运营 |
| 总部管理员 | 全部门店会员查看 |
| 老师 | **仅**查看名下必要会员摘要，不可看全店名单 |
| 财务 | 仅查看与资产风险相关的会员_subset_（从财务入口进入时） |
| 投资人只读 | 不可见 |

### 5.5 页面结构

```
1. 页面头部
   - 返回：会员经营
   - 标题：会员名单
   - 范围：滨江馆 · 全部阶段
   - 摘要：共 1,248 人 · 待跟进 36 · 高风险 12
   - 操作：导出名单（待建设）

2. 会员状态摘要（6 格数字条）
   - S0 新成交 / S1 激活中 / S2 稳定 / S3 活跃 / S4 续费窗 / S5 沉睡 / S6 流失风险

3. 筛选区
   - 门店、会员阶段、活跃状态、风险标签、负责人、卡项、关键词

4. 会员列表
   - 列：姓名、阶段、状态、剩余点数、最后到店、负责人、风险标签、跟进状态、操作

5. 批量操作区（勾选后显示）
   - 批量分配负责人（待建设）
   - 批量标记已跟进（待建设）

6. 会员详情抽屉
   - 复用 MemberV2MemberDetail 全字段

7. 跟进记录入口
   - 抽屉内「查看跟进记录（待建设）」

8. 空状态
```

## 15. 建议建设顺序

### 第一阶段：门店日常高频处理（4 页）

| 顺序 | 页面 | 理由 |
|:----:|------|------|
| 1 | 会员名单 / 会员详情 | 最高频；复用现有抽屉；其他名单的基础 |
| 2 | 高余额低耗课名单 | 跨会员 + 财务 + 驾驶舱；业务价值最高 |
| 3 | 退费 / 冻结 / 转卡申请 | 财务核心处理流；复用 finance mock |
| 4 | 完整周排课 / 新增排课 | 教学日常高频；复用 course mock |

| 顺序 | 页面 | 理由 |
|:----:|------|------|

| 6 | 卡项配置 | 产品规则核心；影响会员端和财务 |
| 7 | 积分商城配置 | 产品与权益闭环 |

### 第三阶段：审计与获客（4 页）

| 顺序 | 页面 | 理由 |
|:----:|------|------|

| 10 | 合同模板绑定 | 卡项配置前置依赖 |

### 第四阶段：治理与数据（P2）

权限矩阵 → 消息通知 → 跨店结算 → BI 报表

### 排序逻辑

1. **先解决门店日常高频处理** — 店长 / 管家 / 财务每天要用
2. **再解决规则配置** — 总部 / 运营后台治理

| 每个二级页面先做 mock | 独立 `*Secondary.viewModel.ts` |
| 不接真实接口 | 数据本地 build |
| 不做真实审批 / 退款 / 排课 / 上下架 | 全部 toast |
| 每页完成后截图验收 | 确认后再做下一页 |

### 16.2 每页必检清单

- [ ] 有返回一级页入口
- [ ] 有页面头部（标题、范围、摘要）
- [ ] 有筛选区（按规划裁剪）

- [ ] 遵守敏感信息和业务红线
- [ ] `npm run build` 通过

### 16.3 实施时的文件边界（建议）

每增一个二级页面，预计新增：

```
components/v2/{module}/
  {Module}Secondary{X}Page.tsx      # 二级页面
  {module}Secondary{X}.viewModel.ts # 独立 mock
  {module}Secondary{X}.css          # 样式（或扩展现有 css）
```

一级页改动（最小）：

- 将对应 `toastMessage` 改为导航到二级页
- 或增加 `onNavigateSecondary(pageId)` 回调

**初期可不改 `App.tsx` 路由**，可用一级页内 `viewMode` 切换；路由化在实施第 4 页后统一评估。

## 17. 禁止事项

### 17.1 结构与产品定位

- 不要把二级页做成 Excel 大表
- 不要破坏一级页已有结构
- 不要新增过多一级菜单（左侧仍 9 项）
- 不要把会员名单做成电话销售 CRM
- 不要把排课页做成普通 CRUD 后台
- 不要让店长直接改价格 / 退费规则 / 合同

### 17.2 敏感信息与财务红线

- 不要显示老师工资或课时费
- 不要暴露会员完整手机号、身份证、住址、银行卡
- 不要混淆实收、确认收入、预收负债、经营利润
- 不要把积分当现金
- 不要把赠送权益计入退费

### 17.3 交互与文案红线

- 不要出现 AI 推荐
- 不要自动群发
- 不要真实审批通过文案
- 不要真实退款成功文案
- 不要真实排课成功文案
- 不要真实卡项上下架成功文案
